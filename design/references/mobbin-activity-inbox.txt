Rules for our Activity list

1. Row anatomy has three slots.
   - Left: a 32px actor avatar with a 14px type badge at the bottom right. Events with no person behind them show the type glyph in a grey-3 circle instead.
   - Middle, two lines: the item name (one line, truncated), then a detail line in grey-11.
   - Right: time in grey-10 at 12px.
   - The unread dot goes in a 12px left margin outside the row, so text never shifts. Rows are 56px tall on desktop and 64px on phone.

2. Copy: the badge carries the verb and the text carries the nouns. Each row is badge | line 1 | line 2:
   - Reply on my thread: ↩ | {thread title} | {First name}: {first line of reply}
   - Answer on my request: ✓ | {request title} | {First name}: {answer excerpt}
   - En route: → | {request title} | {First name} → {destination}
   - Location change: pin | {request title} | {old} → {new}
   - New request: + | {request title} | {location} · {First name}
   - Never write "replied to", "has", "ago" or a full sentence. Time reads now / 4m / 2h / Tue / 3 Nov.
   - The aria-label carries the full sentence: "Dana replied on Bay 3 restock: two left. 4 minutes ago. Unread."

3. Grouping: one row per item, not per event.
   - A new event on an item already listed moves its row to the top, rewrites line 2 to the latest event, swaps in that event's badge and marks the row unread again.
   - Multiple actors stack as two overlapping avatars and "Dana, Lee +2: {latest excerpt}".
   - Use only two section labels: Today and Earlier.

4. Unread is a dot plus font weight, nothing else.
   - Unread: a grey-12 dot and a medium-weight title.
   - Read: no dot and a regular-weight grey-11 title.
   - No tinted background and no blue: in a monochrome UI the dot is the only accent.
   - Read rows stay in the list, as in Brex and Linear, and drop off after 30 days.

5. An item counts as read when you open it, from the list or any other route (deep link, the board, the thread itself).
   - Read state belongs to the item, not the notification.
   - Opening the list, scrolling or hovering marks nothing read.
   - No separate "done" state in v1. GitHub's read-vs-done split is a power-user feature we don't need yet.

6. The bell badge counts unread items, not events: five replies on one thread count as 1.
   - It never counts your own actions.
   - It is hidden at 0, shows 1–9, then "9+".
   - It does not clear when the list opens. It drops by one as each item is opened (Height 3 → 2, Linear 7 → 5), or goes to 0 on mark-all-read.
   - Screen-reader label: "Activity, 3 unread".

7. Header, read-all and empty state.
   - Header: "Activity" on the left. On the right, one double-check IconButton (tooltip "Mark all read"), disabled when nothing is unread.
   - Mark-all-read shows an undo toast for about 5 seconds, like GitHub's "2 items marked as read".
   - Filtering is an All / Unread SegmentedControl only. Five event types don't need Slack- or Threads-style filter chips.
   - Empty state: one line-art glyph and "Nothing new" (as in Linear and Slack), with no subline or joke.

8. Phone sheet vs desktop popover.
   - Below 768px (Radix `sm`), the bell opens a full-height sheet like Brex's: centred title and ✕. Radix Themes has no sheet component, so build it on Dialog.
   - At `sm` and up, use a Popover anchored to the bell, about 380px wide and at most 480px tall, scrolling inside.
   - Tapping a row navigates and closes either one.
   - Keep the popover. Move to a full Activity page with a Linear/Height-style list and detail split only if you add filters or multi-select.
